Release notes · 3.6.0 · unreleased

A bar, a port, and a minute back

Nothing here is a new idea. It is the work that turns a downloader you tolerate into one you can leave running: a terminal that shows what is happening, ports that move when they have to, a seeder that answers the same questions it asks, and a stalled single-seed transfer that no longer takes a minute to give up.

in main · dach-a · Rust, no runtime · ~3 MB binary

Not tagged yet. This page tracks the Unreleased section of the changelog. The download buttons on the front page still serve 3.5.0, the last release; building from source is the only way to run these changes today.

What is on main

A progress bar worth watching

The CLI draws one bar and repaints it in place instead of printing a line per update: a gradient fill in the same blues as the window, a green set once the piece count settles, a braille spinner, the aggregate rate, ETA and peer count. It is not a separate source of truth — it reads the same engine counters the GUI does, which is why paused is amber, done is green and failure is red in both.

When the output is not a terminal, when NO_COLOR is set, or on a Windows host without ANSI support, it falls back to plain text that never repaints. Piping ftc into a file stays readable.

Ports you can move

--port <n> sets the announce and listen port for a download, and --swarm-port <n> does the same for ftc serve. Two clients on one machine, or a network that throttles 6881, no longer means one of them quietly does nothing.

The seeder answers magnets

Metadata exchange used to be a receiver-only feature: the client asked peers for the info dictionary but never served it. A process running as a seed now replies to an extension handshake by advertising ut_metadata and its metadata size, then hands out exact dictionary bytes. Out-of-range requests are rejected, per BEP 9.

The practical effect: a swarm made only of Footorrent instances can bootstrap from the seed itself. No third-party client has to be present just to describe the torrent.

The minute that is not coming back

3.5.0 resolved magnets properly and then, in some swarms, still crawled. Piece workers exited the moment their address queue ran dry and dialled a fresh connection per piece, so a lone seeder collapsed into one surviving trickle and the job ended with “pieces still missing after retries”.

Workers now hold one negotiated connection across many pieces. When the swarm goes quiet they park and refill through tracker bursts, with a minimum gap so hungry workers do not stampede the tracker. SHA-1 verification moved into the block fetch, so a corrupt peer is disconnected before its bytes reach disk rather than after.

Measured on the same 120 MB torrent from a single seed. Before: 52 s, then failure. After: 0.7 s uncapped, and 20 s with a 6 MB/s cap — the cap being what the test asked for, not what the link gave.

Installers that say what they did

install.sh used to skip checksum verification in silence when shasum or sha256sum was missing, or when a release shipped no SHA256SUMS. Each of those cases, plus FTC_NO_VERIFY, now prints its own SKIPPED line to stderr. Nobody should finish an install believing a digest was checked when it was not.

Both installers are also checked in CI on every push and pull request: shellcheck for the shell script, PSScriptAnalyzer at Error and Warning for the PowerShell one. These are not proof of correctness — they are proof that the quiet failure modes we already hit stay fixed.

License and front door

The project is now GPL-3.0-or-later. MIT let anyone take the code private, which fits poorly with a tool whose whole argument is that downloads should stay free of accounts and telemetry. Copyleft is what the rest of the torrent ecosystem uses; a fork or an app built on ftc-core releases its sources under the same terms. LICENSE carries the canonical text and nothing was added on top of it.

The README was rewritten around what you actually see — the download-manager window, the terminal bar, real captures in assets/demo/ instead of mockups — and the site you are reading now shares the window's palette token for token.

What 3.6.0 will not fix

A dead swarm stays dead, and a magnet with a truncated info hash still has nothing to query. Metadata exchange is served by seeds, not by every peer in a swarm: a client that only leeches will not describe a torrent to anyone else.

The terminal bar is a renderer, not a scheduler — if the underlying transfer stalls, the bar will show a stall accurately rather than invent movement.

Until it ships

Build it from main with the README instructions, or stay on 3.5.0. The authoritative list of changes is the changelog; this page is the longer version of its Unreleased section and will get a date when the tag does.
